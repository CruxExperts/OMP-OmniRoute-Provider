## 1.0.5 — 2026-11-10

- Support explicit source-proven empty-body HEAD response variants and a qualified
  transport that preserves headers without downloading an entity. Unresolved
  return branches cannot establish empty-body evidence; resolved re-exports retain
  their evidence. HEAD qualification still requires separate handler and ingress
  observations rather than borrowing GET results.

- Qualify HEAD `/livez` with separate pinned-handler outcomes and fresh isolated
  framework ingress for anonymous, invalid-credential, and session requests.
  Refresh affected existing receipts from newly executed handler observations.
  This brings qualified operations to 20; other operations retain their gates.

- Extend separately source-bound ingress policy observations to fallback-chain,
  provider-node, and provider cc-alias reads. These reachability controls do not
  establish real handler authorization, persistence, or cold database lifecycle.

- Qualify the fallback-chain read with separate pinned-handler and hosted policy
  observations. An empty process-local map does not establish empty durable
  storage after a swallowed initial load failure; fallback writes remain unavailable.

- Permit authenticated npm package absence during protected first publication;
  preserve registry-error stops and uncertain-publication reconciliation without
  replay. Authentication does not establish publish entitlement.

- Permit explicit private source derivation for repair research with pinned base,
  commit, and file digest checks. Prior signature evidence is recorded, not freshly
  verified; derived startup results do not qualify the official source.

- Qualify the model-capability-overrides read with an independent pinned-handler
  observation and separately retained ingress policy evidence. Capability writes
  remain unavailable; the fixture does not establish cold database initialization.

- Retain fresh hosted ingress policy evidence alongside independent pinned-handler
  outcomes for five combo reads and metrics reset. The candidate now has 18
  qualified operations, 16 source-evidenced exceptions, and 1,258 unqualified
  operations out of 1,292. This does not establish cold database initialization
  or qualify the remaining combo mutations.

- Bind six combo method/path policy observations to their original route digests,
  keeping framework reachability separate from actual handler evidence. Reject
  incomplete or mismatched method, path, policy, and source records.

- Demonstrate the pinned auto-combo read/duplicate capability difference with
  actual source handlers. Unchanged GET output cannot certify an unchanged
  capability-resolved duplicate target; no operation is newly qualified.

- Exercise pinned raw skill Markdown reads against disposable files, including
  response headers and sanitized errors. External fallback and ingress evidence
  remain required before this operation can become available.

- Give startup credential lookup and live discovery their own bounded budgets,
  independent of configuration ACL reads. Capture separate, sanitized Windows
  diagnostics for persisted-inference startup when diagnostics are enabled.

- Add configurable bounded fresh inference attempts for transient failures,
  including gateway restarts. Cancellation and connection changes stop retries;
  completed tool calls and administration operations are not replayed. The default is
  five total attempts with a 30-second delay; both are configurable, and setting
  `reconnectMaxAttempts` to `1` disables retries.
  The connector holds response text until successful generation instead of
  streaming live tokens. Failed partial output is discarded, and tool calls
  from failed attempts are never started.
- Drain incoming response events independently of the host consumer, retaining
  the native response accumulator without a duplicate per-token event queue.
  Deliver successful output once; reject truncated streams before retrying.
- Preserve pinned Alpine runtime hashes when the original package URL is gone:
  use a retained mirror only after an HTTP 404, and reject any byte or signature
  mismatch. Align the release gate with eligibility schema 3 without relaxing
  operation or platform qualification.
- Canonicalize the native smoke temporary root before checking profile
  containment, including systems whose default temporary path is a symlink.
- Publish a complete native content lifecycle only after a buffered generation
  succeeds. This prevents the host's empty-response recovery from discarding a
  successful tool call and preserves the actual tool result in continuation.
- Compare native canonical extraction paths across Python and JavaScript so
  equivalent macOS temporary paths and Windows path spellings are accepted.
  Wrong destinations and symlinked extracted package directories remain rejected.
- Use native private Windows access-control lists for profile configuration,
  retaining owner/trustee checks and file-identity checks instead of treating
  Windows file modes as proof of privacy.
- Complete the native login command with Tab, wait for its argument hint, then
  submit with Enter. This distinguishes command completion from submission on
  the pinned Windows host. Real provider selection and cancellation remain
  required acceptance evidence.
- Add bounded UTF-8 text transport for explicitly qualified bodyless
  administration reads with finite response projections. Error bodies and
  arbitrary raw output are not exposed; no additional operation is qualified.
- Preserve bounded source, run, archive and verified-host identity before native
  Windows login diagnostics, including when the dialogue is interrupted.
- Rebind a resumed worker's retired OmniRoute API identifier to its active
  connection before inference. Preserve the selected model and thinking level;
  models absent from the current live catalog remain blocked.
- Bind explicitly declared subprocess and dynamic fixture inputs into qualification
  test fingerprints; reject private, duplicate, missing, linked, or escaping inputs.
- Align pinned combo fixtures with current account-label imports and the source's
  fallback-request and skips-per-request metrics without promoting eligibility.
- Sample the research host's bounded trace before timeout termination and bind a
  disposable provider overlay separately from the verified package archive.
  Missing bridge sentinels or incomplete traces remain inconclusive, not Windows
  qualification.
- Keep saving the optional setup-invitation preference outside the native startup
  gate, report persistence failures, and cancel pending writes before commit when
  the session shuts down. This does not bypass setup or credential validation.
- Bound publication readback streams by approved asset lengths and metadata size;
  disable npm publication transport retries so uncertain writes require explicit
  reconciliation instead of automatic replay.
- Refresh the pinned OmniRoute source inventory to 3.8.53 and retire prior active
  operation receipts into immutable history. Changed handlers, framework inputs,
  and test closures require fresh qualification; historical passes do not grant
  candidate administration access.

## 1.0.0 — 2026-10-21

Bring your OmniRoute gateway into Oh My Pi with guided setup, live model
selection, and an optional administration workspace.

### Highlights

- **Guided setup:** configure the gateway and optional services in OMP, with
  masked prompts and native credential storage.
- **Live models:** discover the models your gateway actually serves; optional
  catalogs enrich metadata without inventing runnable model identities.
- **Streaming inference:** use Responses and Chat Completions, including tool
  continuation and cancellation tied to the active connection.
- **Reviewed administration:** inspect source-backed operations, preview the
  affected target, and confirm supported changes. Uncertain outcomes are
  reported honestly and are never automatically replayed.
- **Clear pricing:** distinguish known, unknown, conditional, and stale fields.
- **A refreshed identity:** coordinated SVG/PNG graphics, practical guides,
  generated command references, and accessible historical interface examples.

### Install from GitHub

```text
omp plugin install https://github.com/CruxExperts/OMP-OmniRoute-Provider#v1.0.0
```

Restart OMP, then run `/cruxomni setup`. The existing package identity,
`/cruxomni` commands, `omniroute` provider ID, environment variables, and native
credential configuration remain compatible.

### Distribution and verification

This is a **GitHub release**, with a package archive, source archive, versioned
media ZIP, CycloneDX dependency inventory, release manifest, and SHA-256 checksums.
The GitHub-tag install command uses the tagged source. This release does **not**
publish the package to the npm registry; the manifest's npm target describes
prepared artifacts, not npm publication.

Administration is intentionally limited to **25 qualified operations**;
**1,193 remain blocked**, with **16 source-evidenced exceptions**. The inventory
is not a claim of complete OmniRoute administration coverage. Some confirmed
mutations retain an unknown outcome where upstream persistence cannot be proven.

The declared OMP range is `>=18.12.2 <19`, with source contracts pinned to
OMP `18.12.5` and OmniRoute `3.8.52`. Native release verification covers
**Linux x64 with glibc and OMP 18.12.5**. The other seven platform targets
have **not** been qualified for this release. Existing screenshots are clearly
labeled historical captures. See the generated compatibility and capability
references for precise boundaries.

Source code and documentation use the MIT License. Visual assets retain their
separate project-reference display grant and ownership notices.
